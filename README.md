# ATLAS AI | اطلس AI

اپلیکیشن دستیار هوشمند چندسرویس با رابط فارسی/دری و انگلیسی، برای Android و نسخه وب.

## هویت محصول
- برند: **ATLAS AI**
- نام فارسی: **اطلس AI**
- شعار: **هوشمندی بدون مرز**
- زبان رابط: تشخیص زبان دستگاه؛ فارسی/دری و انگلیسی
- پلتفرم نخست: Android؛ نسخه وب برای دسترسی و نمایش

## قابلیت‌های موجود در کد
- رابط Android با Kotlin و Jetpack Compose
- صفحات اصلی، منوی گروه‌بندی‌شده، حالت روشن/تاریک و تنظیم زبان دستگاه
- گفت‌وگو با موتور آنلاین از طریق تابع Supabase Edge Function با نام `atlas-chat`
- تاریخچه چندگفت‌وگویی محلی در Android؛ ایجاد، بازکردن، ادامه، تغییر نام، جست‌وجو و حذف با تأیید
- نگهداری حداکثر ۳۰۰ پیام در هر گفت‌وگو و سقف ۱۰۰ گفت‌وگوی اخیر در ذخیره محلی
- نسخه وب با گفت‌وگوی آنلاین و صفحات معرفی قابلیت‌ها؛ تاریخچه وب فقط در حافظه نشست مرورگر است
- اتصال Gmail فقط‌خواندنی در کد وجود دارد؛ تأیید OAuth و آزمایش دستگاهی هنوز انجام نشده است

## وضعیت موتور هوش مصنوعی
- تابع `atlas-chat` در Supabase با وضعیت ACTIVE و نسخه ۹ مشاهده شده است.
- کلاینت Android و نسخه وب به endpoint این تابع درخواست می‌فرستند.
- تابع از مسیرهای OpenAI-compatible، Groq، Z.AI و Cloudflare Workers AI پشتیبانی می‌کند؛ هر ارائه‌دهنده فقط در صورت وجود تنظیمات و Secretهای لازم فعال می‌شود.
- وجود Secretهای لازم و دریافت پاسخ موفق از مدل هنوز با درخواست زنده تأیید نشده است.
- endpoint فعلی بدون JWT کاربر منتشر شده است؛ محدودیت درخواست در حافظه Edge نگهداری می‌شود و پایدار نیست. این معماری برای انتشار عمومی گسترده کافی نیست.
- کلیدهای ارائه‌دهندگان فقط باید در Secret Manager سمت سرور باشند؛ هیچ کلید محرمانه‌ای نباید در APK یا JavaScript قرار بگیرد.

## هشدار مهم درباره مقصد Supabase
در بررسی خواندنی پروژه با ref برابر `wwlyvojtsrklcpqsloqz`، ۵۹ جدول در schema عمومی مشاهده شد که نام‌های مرتبط با صرافی، کاربران، کیف‌پول، تراکنش، نرخ و پرداخت دارند. شمار ردیف‌های گزارش‌شده برای این جدول‌ها در زمان بررسی صفر بود. این ساختار با پایگاه داده‌ای که انتظار می‌رود برای یک دستیار هوش مصنوعی مستقل باشد هم‌خوانی روشن ندارد؛ بنابراین هویت و مرزبندی این پروژه باید پیش از هر تغییر در Auth، جدول‌ها، RLS، سهمیه یا ذخیره ابری تأیید شود. هیچ جدول، داده، حساب، تنظیم Auth یا سیاست RLS در این بررسی تغییر نکرده است.

## موارد تکمیل‌نشده
- تأیید مقصد مستقل و امن بک‌اند و تعیین روش ورود کاربر
- احراز هویت JWT و سهمیه پایدار و کنترل سوءاستفاده
- تأیید تنظیمات Secretهای ارائه‌دهنده و آزمایش واقعی پاسخ مدل
- پایگاه داده محلی تراکنشی به‌جای SharedPreferences
- تکمیل ابزارهای فایل، تصویر، صوت، وب و یکپارچه‌سازی‌های خارجی
- تکمیل ترجمه بومی، دسترس‌پذیری و بررسی چیدمان روی دستگاه‌های واقعی
- تکمیل سیاست حریم خصوصی، پشتیبانی و اطلاعات فروشگاه
- دریافت کلید امضای انتشار، ساخت و بررسی AAB امضاشده

## ساخت و انتشار
- GitHub Actions برای اعتبارسنجی دستی Android و ساخت بسته دیباگ پیکربندی شده است؛ تا درخواست صریح کاربر اجرا نمی‌شود.
- workflow ساخت دستی APK دیباگ و workflow اعتبارسنجی AAB امضاشده وجود دارد.
- هیچ AAB امضاشده یا نسخه منتشرشده‌ای در این مرحله تأیید نشده است.
- کلید امضای انتشار هنوز از کاربر دریافت نشده و نباید در مخزن Git قرار بگیرد.
- آماده‌بودن برای انتشار فقط پس از رفع موانع امنیت، اتصال، آزمون دستگاهی، امضا و تکمیل الزامات Google Play اعلام می‌شود.
